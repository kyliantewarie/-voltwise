# Commercial deployment notes

## Editions

| Edition | Features | Licence feature tag |
|---|---|---|
| Core | Battery + EV optimisation, manual tariffs, generic number entities | `core` |
| Pro | MQTT/Modbus adapters, forecast uncertainty, multi-site (one agent per site) | `pro` |

Licence keys are Ed25519-signed by the vendor; only the public key ships in the
product, so a customer cannot mint a key from an environment variable. Keys are
read from `licensing.key_env`, carry a feature list, expiry and optional device
fingerprint, and are never written to plans, logs or support bundles. Offline
licensing is not absolute DRM — a determined user can patch the binary — so
sell the support and update channel, not the cryptographic boundary.

## Installer / multi-site workflow

Each site runs its own VoltWise instance with its own config and licence key.
Installers can manage sites by collecting each site's `diagnostics.json` bundle
(`--diagnostics`) and `metrics.json` (written by the service every cycle).
A fleet dashboard can read those files through the installer's existing
device-management pipeline; no cloud dependency is required.

## Update channel

Releases are published with a `version` in three files, kept consistent by the
audit (single source: `voltwise/_version.py`). Each release includes:

- `audit/AUDIT_REPORT.md`
- `audit/sbom.cdx.json`
- a SHA-256 checksum file generated by `audit/release.py`; it is signed when
  `VOLTWISE_RELEASE_KEY` is configured

Verify the signature (when present) before updating. Security fixes are released on the same
day as the advisory and remain free for the supported release line.
